# Exercise 6.22

It would be possible to represeent a `Picture` as a single list of characters, with `'\n'` characters used to indicate the end of each row. Consider, for example, this picture:

```text
.##.
.#.#
.###
####
```

In our original representation, this picture looks like this:

```text
[".##."," .#.#",".###","####"]
```

In the new representation, it would be:

```text
".##.\n.#.#\n.###\n####"
```

What would this change imply for the various functions we have defined on pictures?

## Code changes

Two functions would become very easy to implement: `printPicture` and `above`. The `printPicture` function would simply print the string, and the `above` function would concatenate two strings with a `'\n'` in between.

However, all other functions such as `flipV`, `flipH`, `beside`, `rotate`, and `scale` would become significantly more complex. This is because these functions rely on the row and column structure of the picture, which is now flattened into a single string. To implement these functions, we would need to first parse the string into its row and column structure, perform the desired operation, and then convert it back into a single string. This parsing and reassembly process would add considerable overhead to each function.

In Haskell, we could use the `lines` function to split the string into a list of strings (rows), and the `unlines` function to join a list of strings back into a single string. So, for example, the vertical flip function could be implemented using the original `flipV` function as follows:

```haskell
flipV' :: String -> String
flipV' = unlines . flipV . lines
```
