An alternative representation of Picture is the type

```haskell
type Picture = [[Bool]]
```

where `True` represents a black pixel and `False` a white pixel.

## Code changes

If we were to use this presentation, then most functions (flipV, flipH, beside, above, rotate) would work identically, just replacing `Char` with `Bool`. Only the inversion function and the padding function would need explicit changes.

The inversion function would become:

```haskell
invertColour :: [[Bool]] -> [[Bool]]
invertColour pic = [[not b | b <- line] | line <- pic]
```

And the padding function would just need to be modified to use `False` instead of `'.'`:

```haskell
padToRect :: [[Bool]] -> [[Bool]]
padToRect pic =
  let maxLen = maximum (map length pic)
  in [line ++ replicate (maxLen - length line) False | line <- pic]
```

## Advantages

1. **Simplicity**: The Bool representation is simpler for binary images (black and white) since it directly represents the two states of a pixel. The logic of operations like inversion becomes more straightforward.
2. **Memory Efficiency and Performance**: Using Bool can be more memory efficient than using Char, especially if the image is large. Operations on Bool can also be faster since they involve simple logical operations rather than character manipulations. In Haskell, however, Bool is not guaranteed to be packed into a single bit, unless you use specific libraries for bit manipulation.
3. **Type Safety**: The Bool type makes it clear that there are only two possible values for each pixel, reducing the chance of errors. You cannot accidentally use an invalid character.

## Disadvantages

1. **Limited Color Representation**: The Bool representation is limited to black and white images. With Char, you can represent multiple colors or shades (e.g., using different characters for different colors).
2. **Readability**: Using characters like `'.'` and `'#'` can make it easier to understand the image at a glance. This can be mitigated by using a custom show function to convert Bool to Char for visualization.
3. **Conversion Overhead**: You may need to convert between Bool and Char representations if you want to display the image or work with other libraries that expect Char.
