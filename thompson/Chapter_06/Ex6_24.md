# Exercise 6.24

In the previous exercise, we defined pictures in a more compact way, using
run-length encoding, where each line is represented as a list of pairs
`(n,c)`, meaning that the character `c` is repeated `n` times. Thus, the definition of `Picture` became:

```haskell
type Picture = [[(Int, Char)]]
```

The functions defined there assume a normalized representation, where no two consecutive pairs have the same character, and no pair has a count of zero. The question asked in this exercise is whether these functions preserve this invariant.

This is clearly the case for the functions `flipH`, `flipV`, and `rotate`, since they just rearrange rows or reverse the order of pairs in a row. They do not change characters or counts, so if the input picture is normalized, the output will be as well.

It is also true for `scale`, which merely multiplies the counts by a factor, but leaves characters and order intact.

Lastly, the functions `beside`, `above`, and `padToRect` also preserve normalization. However, in these cases we had to take special care to ensure that the resulting picture remains normalized. For example, in `beside`, we merge the last pair of the first picture with the first pair of the second picture if they share the same character, in order to avoid consecutive pairs with the same character. And in `padToRect`, we only add padding pairs (n, '.') where necessary, and combine with the last pair if it is already a '.' to avoid duplicates.

Thus, all the functions defined in the previous exercise do indeed preserve the normalized RLE representation of pictures.
