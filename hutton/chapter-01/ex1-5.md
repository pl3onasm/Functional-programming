# Exersice 1.5

Given is the definition of *qsort* presented in exercise 1.4.

The question is what the effect would be if we replaced the `<=` operator in the definition of *smaller* with `<`.

The modified definition of *qsort* thus becomes:

```haskell
  qsort :: Ord a => [a] -> [a]
  qsort [] = []
  qsort (x : xs) = qsort smaller ++ [x] ++ qsort larger
    where
      smaller = [a | a <- xs, a < x]
      larger  = [b | b <- xs, b > x]
```

The effect of this modified version is that elements that are equal to the pivot element `x` are not included anymore. These elements are excluded because they no longer fall into either the *smaller* or *larger* partitions. In other words, the function now produces a sorted list that discards all duplicate elements.

To verify this, we consider the example `qsort [2,2,3,1,1]` and evaluate it step by step.

```text
    qsort [2, 2, 3, 1, 1]
  =   {applying the recursive case}
    qsort [1, 1] ++ [2] ++ qsort [3]
  =   {applying the recursive case}
    (qsort [] ++ [1] ++ qsort []) ++ [2] 
    ++ (qsort [] ++ [3] ++ qsort [])
  =   {applying the base case}
    ([] ++ [1] ++ []) ++ [2] ++ ([] ++ [3] ++ [])
  =   {applying ++}
    [1] ++ [2] ++ [3]
  =   {applying ++}
    [1, 2, 3]
```

Thus, we see that for the input list `[2, 2, 3, 1, 1]`, the modified *qsort* function produces the output `[1, 2, 3]`, which is the sorted version of the input list without duplicates.
