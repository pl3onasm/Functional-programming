# Exercise 17.1

We are given the following language extension which allows us to write expressions with exceptions:

```haskell
    data Expr = Val Int
              | Add Expr Expr
              | Throw
              | Catch Expr Expr
```

Informally, *Catch x h* behaves as the expression *x* unless evaluation of *x* throws an exception, in which case the catch behaves as the handler expression *h*. An exception is thrown if evaluation of *Throw* is attempted.

The semantics of this language is given by a rewrite of the original evaluation function eval for arithmetic expressions. In this rewrite, we use the Maybe type to denote an exceptional value in the case of *Nothing*, and a normal value in the case of *Just n*, where *n* is the evaluated integer.

```haskell
    eval :: Expr -> Maybe Int
    eval (Val n)     = Just n
    eval (Add x y)   = 
      case eval x of
        Just n -> case eval y of
                    Just m -> Just (n + m)
                    Nothing -> Nothing
        Nothing -> Nothing
    eval Throw       = Nothing
    eval (Catch x h) = 
      case eval x of
        Just n -> Just n
        Nothing -> eval h
```

For the original language, we had the following correctness equations, which expressed the relationships between the semantics, compilers and virtual machine:

```haskell
    exec (comp e)    s = eval e : s 
    exec (comp' e c) s = exec c (eval e : s)
```

where the stack the virtual machine operates on is of type:

```haskell
    type Stack = [Int]
```

and the compilation function transforms an expression into code for the virtual machine represented by the type:

```haskell
    data Code = HALT
              | PUSH Int Code
              | ADD Code
```
  
For the extended language, we need to rewrite these correctness equations to account for the possibility of exceptions. First, we modify the type for *comp'* to reflect the fact that evaluation may fail:

```haskell
    comp' :: Expr -> Code -> Code -> Code
```

That is, *comp'* now takes two code continuations as arguments: one for the case where the expression successfully evaluates, and one for the case where evaluation fails and an exception is thrown. The signature of the top-level *comp* function remains unchanged:

```haskell
    comp :: Expr -> Code
```

The desired behavior of *comp'* and *comp* is that they compile an expression into code that, when executed, will either yield a value on the stack or continue with the appropriate code continuation in the case of an exception.

This intended behavior is formalized by the following correctness equations for the extended language and serve as specifications for the compilation functions:

- **Correctness equation (1)**

```haskell
    exec (comp e) s = 
      case eval e of         
        Just n  -> n : s                     
        Nothing -> s        
```

- **Correctness equation (2)**

```haskell
    exec (comp' e sc fc) s = 
      case eval e of  
        Just n  -> exec sc (n : s)           
        Nothing -> exec fc s                 
```

where *sc* and *fc* are the success and failure code continuations, respectively.

Our task is to implement the *comp* and *comp'* functions that satisfy the above equations. The definitions for these functions will be calculated by constructive induction on the structure of the expression *e*. We will start from an empty set of Code constructors and add constructors to the type as we derive the definitions for *comp* and *comp'*. These additions will follow naturally from the need to satisfy the correctness equations.

---------------------------------

We start by calculating the definition for *comp'* from (2) by constructive induction on the expression *e*. In each case we start from the LHS of equation (2) which is of the form *exec (comp' a) s*, and proceed by using its specification given by (2). Then we rewrite this into the form *exec c s*, and from this we may then conclude that by defining *comp' a = c* the correctness equation (2) is satisfied.

## BASE CASES
  
### Base case 1: e = Val n
  
```text
      {LHS of equation (2)}
    exec (comp' (Val n) sc fc) s 
  =   {specification for comp'}
    exec sc (n : s)
  =   {we define exec (PUSH n sc) s = exec c (n : s)
       to bring the stack argument in the right shape and
       satisfy (2); Code type is extended with PUSH}
    exec (PUSH n sc) s
```

Thus, by using the specification and rewriting this into the form *exec c s*, we can conclude that the following definition satisfies the correctness equation (2):

```haskell
comp' (Val n) sc fc = PUSH n sc
```

This definition ensures that if the expression *Val n* is evaluated, we continue with the success continuation *sc* and push the value *n* onto the stack.

### Base case 2: e = Throw

```text
      {LHS of equation (2)}
    exec (comp' Throw sc fc) s 
  =   {specification for comp'}
    exec fc s
```

Hence, the following definition satisfies the correctness equation (2):

```haskell
comp' Throw sc fc = fc
```

This definition ensures that if the expression *Throw* is evaluated, we continue with the failure continuation *fc*.

## INDUCTIVE CASES

### Inductive case 1: e = Catch x h

```text
    _____________________________________________
      Induction hypothesis:

        p(x): exec (comp' x sc fc) s = 
                case eval x of
                  Just n  -> exec sc (n : s)
                  Nothing -> exec fc s

        p(h): exec (comp' h sc fc) s = 
                case eval h of
                  Just m  -> exec sc (m : s)
                  Nothing -> exec fc s
    _____________________________________________

      {LHS of equation (2)}
    exec (comp' (Catch x h) sc fc) s

  =   {specification for comp'}
    case eval (Catch x h) of
        Just n  -> exec sc (n : s)
        Nothing -> case eval h of
                     Just m  -> exec sc (m : s)
                     Nothing -> exec fc s

  =   {induction hypothesis p(h)}
    case eval x of
        Just n  -> exec sc (n : s)
        Nothing -> exec (comp' h sc fc) s

  =   {induction hypothesis p(x)}
    case eval x of
        Just n  -> exec sc (n : s)
        Nothing -> exec (comp' x sc (comp' h sc fc)) s
```

Thus, by using the specification and rewriting this into the form *exec c s*, we can conclude that the following definition satisfies the correctness equation (2):

```haskell
comp' (Catch x h) sc fc = comp' x sc (comp' h sc fc)
```

This definition ensures that if *x* evaluates successfully, we continue with the success continuation *sc*, and if it fails, we evaluate the handler *h* with the same success and failure continuations.

### Inductive case 2: e = Add x y

```text
    ___________________________________________
      Induction hypothesis:
      
        p(x): exec (comp' x sc fc) s = 
                case eval x of
                  Just n  -> exec sc (n : s)
                  Nothing -> exec fc s

        p(y): exec (comp' y sc fc) s = 
                case eval y of
                  Just m  -> exec sc (m : s)
                  Nothing -> exec fc s
    ___________________________________________

      {LHS of equation (2)}
    exec (comp' (Add x y) sc fc) s

  =   {specification for comp'}
    case eval x of
      Just n -> case eval y of
                  Just m -> exec sc (n + m : s)
                  Nothing -> exec fc s
      Nothing -> exec fc s

  =   {We want to apply the induction hypothesis p(y), 
       but in order to do so, we first need to get the  
       stack arguments to match the required shape.
       The first step is to adjust the stack argument 
       of the Just case for eval y by unfolding the top  
       stack element and defining:
         exec (ADD c) (m : n : s) = exec c (n + m : s)
       This extends the Code type with constructor ADD}

    case eval x of
      Just n → case eval y of
                 Just m → exec (ADD sc) (m : n : s)
                 Nothing → exec fc s
      Nothing → exec fc s

  =   {The second step to get the stack arguments into 
       the right form is to modify the stack argument of  
       the Nothing case for eval y by removing and  
       ignoring the top stack element, and defining:
         exec (POP c) (_ : s) = exec c s
       This extends the Code type with constructor POP} 

    case eval x of
      Just n → case eval y of
                 Just m → exec (ADD sc) (m : n : s)
                 Nothing → exec (POP fc) (n : s)
      Nothing → exec fc s

  =   {induction hypothesis p(y)}
    case eval x of
      Just n → exec (comp' y (ADD sc) (POP fc)) (n : s)
      Nothing → exec fc s 

  =   {induction hypothesis p(x)}
    exec (comp' x (comp' y (ADD sc) (POP fc)) fc) s
```

Thus, by using the specification and rewriting this into the form *exec c s*, we can conclude that the following definition satisfies the correctness equation (2):

```haskell
comp' (Add x y) sc fc = 
  comp' x (comp' y (ADD sc) (POP fc)) fc
```

---------------------------------

We conclude by calculating the definition for the top-level compilation function *comp*. We do this by using its spefication given by correctness equation (1). The goal then is to rewrite this in terms of the definition of *comp'* we have just derived.

```text
      {LHS of equation (1)}
    exec (comp e) s

  =   {specification for comp}
    case eval e of
      Just n  -> n : s
      Nothing -> s

  =   {In order to be able to apply (2) we need to
       supply the success and failure continuations
       for the case of a successful evaluation and
       a failure, respectively. We can do this by
       defining a default continuation which simply
       halts the execution and returns the stack
       unchanged. This is done by defining:
          exec HALT s = s
       This extends the Code type with constructor HALT}

    case eval e of
      Just n -> exec HALT (n : s)
      Nothing -> exec HALT s

  =   {applying the specification for comp' from (2)}
    exec (comp' e HALT HALT) s
```

Thus, we can conclude that the following definition satisfies the correctness equation (1):

```haskell
comp e = comp' e HALT HALT
```

## Final summary

Through this process, we have derived the definitions for both *comp* and *comp'* that satisfy the correctness equations for the extended language with exceptions. The final definitions are:

```haskell
comp :: Expr -> Code
comp e = comp' e HALT HALT

comp' :: Expr -> Code -> Code -> Code
comp' (Val n) sc fc = PUSH n sc
comp' Throw sc fc = fc
comp' (Catch x h) sc fc = comp' x sc (comp' h sc fc)
comp' (Add x y) sc fc = comp' x (comp' y (ADD sc) (POP fc)) fc
```

These definitions ensure that the semantics of the extended language with exceptions is correctly captured by the compilation process, allowing for both successful evaluations and handling of exceptions as specified.

The Code type has been extended throughout the derivation process and has the following final definition:

```haskell
data Code = HALT
          | PUSH Int Code
          | ADD Code
          | POP Code
```

The virtual machine operating on this code will execute the compiled expressions according to the semantics defined by the correctness equations, handling exceptions appropriately. The HALT constructor signifies the end of execution, while PUSH, ADD, and POP allow for stack manipulation during the execution of the compiled code.

```haskell
type Stack = [Int]

exec :: Code -> Stack -> Stack
exec HALT s = s
exec (PUSH n c) s = exec c (n : s)
exec (ADD c) (m : n : s) = exec c (n + m : s)
exec (POP c) (_ : s) = exec c s
```
